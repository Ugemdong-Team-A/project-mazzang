# 전투 구조 확장 계획

아직 구현하지 않은 플레이어 전투 구조와 행동의 검토 방향을 기록한다.
구현이 완료된 내용은 현재 구조에 맞게 정리해 `Architecture.md`로 옮긴다.

## 지연 돌진 공격

- 공격 입력 순간에 방향을 한 번 확정한다.
- 준비 애니메이션, 중간 또는 마지막 돌진, 실제 판정은 모두 같은 확정 방향을 사용한다.
- 돌진 시점에 마우스 방향을 다시 읽지 않는다.
- 특수하게 방향을 바꾸는 공격은 새 Aim을 읽는 대신 확정 방향 기준의 로컬 각도나 배율로 표현한다.

## 눌렀다 떼는 Cast 공격

- 기본 흐름은 `누름 → Cast → 마지막 자세 유지 → 뗌 → Main/판정 → Recovery`이다.
- Cast 도중 버튼을 떼면 Cast가 끝난 직후 Main을 실행하도록 예약한다.
- 유지 중에는 별도 Hold 클립 없이 Cast의 마지막 자세를 유지할 수 있어야 한다.
- 방향과 Facing은 누른 순간 확정하고 행동이 끝날 때까지 유지한다.
- 실제 판정은 Main 단계에서만 실행한다.
- 최소·최대 유지 시간과 차지 보너스는 필요할 때 선택 설정으로 확장한다.

두 기능 모두 무기 구현이 Animator를 직접 조작하지 않는다. 무기 행동 상태가 단계와 확정 방향을
발행하고, `PlayerAnimation`이 공통 `ActionAnimationData` 재생 경로로 표현한다.

## 투사체 발사 주체 공용화

- 투사체 기능과 예측 범위가 늘어나면 풀·키 매칭·생성을 공용 `ProjectileEmitter`로 분리한다.
- 무기와 스킬은 같은 Emitter 계약을 사용하고, 실제체·예측체는 구체 발사자를 모른 채 보간을 담당한다.

## 플레이어 증강 상태

- 증강을 도입하면 선택·스택처럼 매치 중 변하는 원천 상태는 플레이어의 Networked Tick 컴포넌트가 권위 있게 소유한다.
- 각 Tick에는 합산된 불변 배율만 `PlayerTickState`로 공개하여, 소비 컴포넌트가 구체 증강을 직접 알거나 기본 데이터를 수정하지 않게 한다.
- 능력치 분류와 합산 규칙은 실제 증강 기획이 확정될 때 결정한다.

## 패링 사용자 확장

- 장비 유무와 관계없이 패링하는 주체가 하나의 좁은 `IParryUser` 계약으로 최종 사용자 배율을 제공한다.
- 기본 패링과 장착 무기는 구체 증강 컴포넌트를 모르고, 선택적인 자체 기본값과 사용자 배율만 합성한다.
- `IParryUser`는 무기나 패링 영역을 역참조하지 않으며, 성공 순간의 최종값은 기존 `ParryHit`에 스냅샷한다.
- `ParryData`는 소비자의 기준 Transform이나 현재 크기를 모르고 기본 지속시간·범위·오프셋·반사 배율만
  보관한다. `PlayerParry`와 패링 무기는 별도의 좁은 기준점 계약에서 판정 기준 Transform과 크기 배율을
  받아 최종 `Origin`과 범위를 합성하며, `ParryRegistry`는 해당 Transform을 직접 참조하지 않는다.
- 방패도 중복 직렬화 필드 대신 공통 `ParryData` 타입을 참조하되, 공유 쿨다운·입력·방향 고정 같은
  무기 행동 정책은 계속 `ShieldWeapon`이 소유한다.
- 호 각도와 반경은 반사된 투사체를 강화하는 `ParryProjectileModifiers`에 섞지 않고 패링 범위 보정으로
  분리한다. 각 `IParryVolume`이 기본 범위와 사용자 보정을 합성한 최종 반경·반각을 판정과 연출에 제공한다.
